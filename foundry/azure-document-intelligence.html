The Architecture

Four Layers from Documents to Intelligence

A complete intelligent document management solution addresses four interdependent layers. Microsoft has native capabilities at each — the architecture design determines how they connect and how far each layer needs to extend into Azure.

1
Foundation · Classify at the source

Ingest & Classify

Azure Content Understanding in Azure AI Foundry uses generative AI and natural-language schemas to extract structured data, tables, figures, and semantic content from complex documents. Azure AI Document Intelligence v4.0 is the GA option for deterministic, high-volume structured and semistructured extraction, including prebuilt and custom models. Apply content-type and security classification before documents enter downstream systems.

Azure Content Understanding (Foundry) · Azure AI Document Intelligence · M365 Document Processing
2
Findability · Enrich the index

Search & Enrich

Index SharePoint content and metadata using the preview indexer. Enrich at indexing time using the Content Understanding Skill for GA extraction and fixed-size chunking (semantic chunking and image descriptions require a preview API), the GenAI Prompt Skill for LLM-powered summarization and image verbalization, and the Document Layout Skill for structure-aware parsing. Build a metadata-rich, hybrid-search-capable index.

Azure AI Search · Content Understanding Skill (GA) · GenAI Prompt Skill (GA) · Document Layout Skill (GA)

The Microsoft Stack

Six Azure Capabilities Powering This Solution

Microsoft brings a layered ecosystem — native SharePoint content services, configurable Azure AI, and Purview as the compliance control plane. Each capability plays a specific, non-overlapping role in the architecture.

01
🧠

Azure Content Understanding

Available in Azure AI Foundry Tools, Content Understanding uses generative AI to process documents, images, video, and audio into structured output. It can preserve document structure, tables, figures, and annotations in RAG-ready Markdown or schema-aligned JSON. It also offers optional per-field confidence scores and source grounding for human review workflows. Azure AI Document Intelligence v4.0 remains the GA choice for established, deterministic forms-based extraction pipelines.

02
🏷️

Microsoft 365 Document Processing

SharePoint-native AI services including taxonomy tagging, OCR, prebuilt document processing, structured and unstructured document models, autofill columns, and content assembly for document libraries.

03
✨

AI in SharePoint

Native AI features built into SharePoint document libraries: summarize files, compare documents side-by-side, ask questions about file content, create autofill columns, and trigger rules and workflows from file content.

04
🔍

Azure AI Search

Enterprise search with the SharePoint Online indexer, a GA suite of enrichment skillsets — Content Understanding Skill, GenAI Prompt Skill, and Document Layout Skill (all GA April 2026 or earlier) — hybrid keyword and vector search, semantic ranking, and document-level security trimming. Knowledge Bases (GA April 2026) provide the agentic retrieval foundation; LLM-assisted multi-source query planning and answer synthesis require the preview API. SharePoint ACL support for document-level permissions is in preview.

05
🤖

Azure OpenAI + RAG

Two retrieval approaches. Classic RAG with hybrid search and semantic ranking is the GA starting point for controlled pipelines. Knowledge Bases (GA April 2026) — Azure AI Search’s agentic retrieval foundation — support core extractive retrieval across supported knowledge sources. LLM-assisted query planning and citation-backed answer synthesis across search index, blob, OneLake, and web sources require the preview API. Connect Knowledge Bases to Azure AI Foundry agents via Foundry IQ (preview) for end-to-end agentic document workflows.

06
🛡️

Microsoft Purview

The compliance and governance control plane: sensitivity labels and label policies, data classification, DLP, auditing, eDiscovery, data lifecycle management, and governance of AI agent interactions across Microsoft 365 and Azure. In preview, Knowledge Base retrieve responses can include sensitivity label metadata per retrieved document — surfacing Purview classification directly alongside grounded content at query time.

Microsoft 365 Document Processing

Meeting Preparation

Six Points to Lead the Conversation

The first call should be a discovery and solution-mapping session — not a product demo. These six principles define the right posture for a productive first engagement.

1

Lead with the operating model, not products

The challenge spans content lifecycle, governance, search, and AI retrieval — not just any single service. Open by aligning on the document lifecycle: source systems, classification needs, search and retrieval goals, and compliance boundaries.

2

Clarify “classification” early

Security classification, content classification, taxonomy tagging, document-type detection, and retention classification are related but distinct design decisions. Surface this distinction in the first 15 minutes to avoid misaligned architecture assumptions.

3

Position Microsoft as a layered ecosystem

Microsoft 365 and SharePoint handle native content services. Azure AI Foundry houses Content Understanding, model deployments, and the GenAI Prompt Skill that power enrichment pipelines. Azure AI Search provides indexing, GA skillsets, and agentic retrieval via Knowledge Bases. Purview handles compliance and information protection. Each layer has a defined, non-overlapping role.

4

Know what is GA vs. what is still preview

Several capabilities reached GA in 2025–2026: Knowledge Bases (April 2026), Content Understanding Skill, GenAI Prompt Skill, and Document Layout Skill in Azure AI Search (April 2026 or earlier). For Knowledge Bases, extractive retrieval and core knowledge-source capabilities are GA, while LLM-assisted query planning, answer synthesis, and configurable reasoning remain preview API features. Also still in preview: SharePoint ACL document-level permissions, Purview sensitivity label metadata in retrieve responses, and some SharePoint list and page indexing scenarios. Validate each against production requirements before committing architecturally.

5

Emphasize security trimming and provenance

For financial-services document retrieval, every LLM answer must be grounded, permission-aware, and traceable to source documents. Enforce access at retrieval time — not only in the UI. Citations are a must-have compliance requirement, not a nice-to-have.

6

Recommend a pilot with representative documents

Retrieval quality, metadata strategy, classification accuracy, and governance behavior should all be validated using real documents and policies — not generic demos. Start with a representative corpus and evaluate before committing to a broad rollout architecture.

Anticipated Questions

Six Questions to Be Ready to Answer

These are the most likely technical and architectural questions to emerge in the first call — with recommended answers grounded in current Microsoft documentation and architecture guidance.

Can Microsoft classify documents at ingestion time?
A —

Yes — three patterns, combinable. (1) M365 document processing for SharePoint-native taxonomy tagging and autofill columns. (2) Azure Content Understanding in Azure AI Foundry for generative, schema-defined extraction from complex or unstructured documents, with optional confidence scores and source grounding for human review. (3) Azure AI Document Intelligence v4.0 for established, deterministic forms-based pipelines using prebuilt models or custom models trained on labeled data. Content Understanding and Document Intelligence can be used together: complex documents through Content Understanding and high-volume structured forms through Document Intelligence.

Can Azure AI Search index SharePoint and preserve permissions?
A —

Yes, with preview capabilities and explicit permission maintenance. The SharePoint in Microsoft 365 indexer indexes files and metadata, detects content changes and deletions, and supports preview ACL-based security trimming. Inherited parent-scope permission changes require an explicit permission resync or reset of affected documents; ordinary incremental indexing is not sufficient. Propagate ACL metadata into every indexed chunk and enforce it at query time. See SharePoint ACL indexing requirements.

Classic RAG or Knowledge Bases — which should we use?
A —

Classic RAG with hybrid search and semantic ranking is the recommended starting point: simple, GA, and easy to validate retrieval quality against your documents. Knowledge Bases — the agentic retrieval foundation in Azure AI Search — reached GA in April 2026. Core extractive retrieval and supported knowledge sources are GA; LLM-assisted query planning, answer synthesis, and configurable reasoning effort require the preview API. Start with classic RAG, then evaluate Knowledge Bases for scenarios requiring multi-source access or preview answer-synthesis workflows.

Can Purview sensitivity labels work in Azure AI Search?
A —

Azure AI Search has documented preview support for extracting Purview sensitivity labels during indexing and enforcing label-based access control at query time for supported sources, including SharePoint in Microsoft 365. This is a preview capability — validate fit and production readiness for specific requirements before designing around it.

Can DLP apply to AI agents and LLM interactions?
A —

Microsoft Purview documents support for AI interaction governance across data classification, sensitivity labels, DLP, auditing, eDiscovery, and compliance management for Microsoft 365 agents. For Azure AI Foundry agents, Purview support includes data classification, sensitivity labels, DLP, and Insider Risk Management in the documented capability matrix.

How do we prevent the LLM from hallucinating on confidential documents?
A —

The architecture must enforce source permissions and sensitivity policies before content reaches the LLM context. Every answer should be grounded in retrieved, permission-trimmed content from Azure AI Search. Citations to source documents are required — both for compliance auditing and for user trust in financial-services retrieval workflows.
