The Four IQ Platforms

Each IQ serves a different role in the knowledge stack. Learn what each one does, how it works, and when to reach for it.

💼

Work IQ

Your organization's digital work life — for Microsoft 365 agents

What it is

M365 Context MCP Servers Memory
  • Intelligence layer for agents working over Microsoft 365 signals and activity
  • Three layers: Data (who, what, where), Memory (personal context), Inference (reasoning over work)
  • Catalog of MCP servers agents can call: Copilot, Calendar, Mail, SharePoint, OneDrive, Teams, User, Word
  • Ignite: richer retrieval, memory and actions are GA; event listening and expanded governance controls are preview. Planned OpenAI/Anthropic integrations are coming soon.

How it works

  • Agent calls a Work IQ MCP server (e.g., mcp-mail, mcp-sharepoint)
  • MCP server queries the Microsoft Graph on behalf of the signed-in user
  • Configure delegated Entra ID scopes, consent and source permissions; test that the integration enforces the intended user's access
  • Memory layer persists user-specific context across sessions
  • Returns structured results the agent can reason over

When to use it

  • Personal productivity agents: email triage, meeting prep, document drafting
  • "Summarize my week across Teams, email, and calendar"
  • Agents that need activity context — who's collaborating with whom on what
  • Shipping into Teams, Outlook, or M365 Copilot surfaces
  • When you already have M365 Copilot licenses

Fabric IQ

Semantic intelligence for your business data — for analytic & operational agents

What it is

Business Ontology Semantic Graph Data Agents
  • New Microsoft Fabric workload that turns Fabric from a data platform into an intelligence platform
  • Capabilities include Ontology, Plan, Graph, Data Agents, Operations Agents and Power BI semantic models; check each item's availability
  • Ontology captures your business entities, relationships, and KPIs so agents speak your language
  • Graph reasons over connected enterprise data in OneLake

How it works

  • Define entities (Customer, Order, Project) and their measures once in the Ontology item
  • Data Agents answer natural-language analytics questions grounded in your data model
  • Operations Agents monitor, act, and trigger workflows on data events
  • Configure and test workspace, item, row- and column-level access for the selected integration
  • Fabric IQ MCP is read-only and delegated-user only: app-only service principals are unsupported, and the calling agent composes DAX
  • Ignite: Microsoft Copilot and Fabric apps integrations are GA; Excel Edit with Copilot, GitHub Copilot ontologies, and new ChatGPT/Claude connectors are preview

When to use it

  • Agents that need to reason over structured business data: revenue, inventory, customers, projects
  • Analytic / BI copilots with correct terminology and metric definitions
  • Cross-domain questions: "Which customers with open support tickets also have renewals this quarter?"
  • Operational automation: auto-detect inventory risks, trigger reorder workflows
  • When you're already on Microsoft Fabric — confirm capacity, region, and preview requirements

Foundry IQ

Reusable retrieval over supported unstructured enterprise sources

What it is

Unified Retrieval Agentic Planning Context Engineering
  • Managed knowledge layer in Microsoft Foundry — reusable endpoints over supported knowledge sources, not every enterprise API
  • Azure AI Search is now Foundry IQ. The service remains unchanged: existing resources, indexes, indexers, endpoints, REST APIs, SDKs, RBAC roles and billing meters continue to work without a code migration.
  • Foundry IQ provides direct indexing and query APIs alongside higher-level knowledge bases, knowledge sources, agentic retrieval, query planning and ranking.
  • Concepts: Knowledge Bases and Knowledge Sources, including supported Azure, SharePoint, OneLake, and web sources
  • Reasoning options: minimal, low, medium, auto. Query planning and answer synthesis at low/medium effort are GA; auto requires a supported preview API.
  • Ignite GA: Serverless, stable REST APIs, SharePoint/File/Azure SQL knowledge sources, agentic retrieval planning and answer synthesis, document-level permissions, semantic chunking and AI image descriptions.
  • Preview: knowledge graphs, Microsoft Retriever 1, Foundry Managed Knowledge, knowledge-base tools, GPT-6 and OpenAI-compatible model profiles, async file ingestion, and Foundry IQ skills for GitHub Copilot CLI.

How it works

  • Agent makes one call to a Foundry IQ knowledge base
  • An optional, supported query-planning model decomposes questions; minimal retrieval does not use LLM planning
  • Sub-queries fan out across the knowledge sources configured for the knowledge base
  • Results are ranked, deduplicated, and consolidated with citations
  • Private ingestion, permission refresh and ACL filtering vary by source and service tier. Serverless does not support private indexer execution or outbound shared private links.
  • User-level access requires a supporting source and explicitly configured permission synchronization. Test revocation and every indexed chunk; Purview enforcement is not universal.

When to use it

  • Agents that need reusable retrieval across supported sources
  • Enterprise RAG patterns — replace hand-written retrieval orchestration
  • Multi-source agents that need reusable knowledge bases over supported enterprise content
  • When you need a single governed, auditable retrieval layer with Purview monitoring
  • Pro-code agents on Foundry or low-code agents in Copilot Studio

Web IQ

The live world outside your tenant — Bing-powered grounding built for agents

What it is

Web Grounding Bing-Powered Agent-Optimized
  • Live web grounding optimized for agent search patterns — not human browsing behavior
  • Work IQ supplies work context, Fabric IQ business meaning, Foundry IQ unstructured content, and Web IQ external knowledge; none is the parent of the others
  • Built on the Bing index, surfaced for agents rather than for search-results pages
  • GA to all Azure customers: Auto, Auto Advanced, Places, Weather and health-aware ranking. Commerce remains private preview.
  • Scopes are available for Web and News requests. With Auto, they filter only Web and News evidence; other answer types can still appear outside the named scope.
  • Bring your own licensed content is supported, and Web IQ is available through REST, MCP and official SDKs.

How it works

  • Agent issues a retrieval call for external, current information
  • Web IQ returns evidence shaped for machine reasoning — structured, citable, and de-duplicated. It does not generate the final answer; your agent or model does.
  • Retrieval patterns are tuned for the multi-hop, iterative way agents search, rather than a single ranked page list
  • Use Scopes to include/exclude approved Web and News locations. For Auto, restrict the response to Web/News evidence when unscoped Places or Weather results are unacceptable.
  • For new Foundry agents, the recommended general web-search tool is powered by Web IQ. Grounding with Bing Search remains a separate GA compatibility option, while domain-restricted custom search still uses Grounding with Bing Custom Search.

When to use it

  • Answers that go stale: market moves, competitor announcements, pricing, regulatory changes
  • Research and analyst agents that must cite public sources
  • Any workflow where “what changed this week?” matters more than what is in your data estate
  • Not for internal knowledge — that is Foundry IQ, Fabric IQ, and Work IQ territory

End-to-End

Building a Smarter Agent with IQ

Pick the smallest useful set of integrations. Use Foundry IQ for supported enterprise-content retrieval, Work IQ for work context, Fabric IQ for business semantics, and Web IQ for public facts. Evaluate them together at the agent layer.

1
Define the Agent

Build in Copilot Studio (no/low-code) or with the Foundry Agent SDK (pro-code). Choose your model.

2
Create a Foundry IQ Knowledge Base

Add only supported content sources, such as a Search index, Blob, OneLake or SharePoint. Verify permission support per source.

3
Add Work IQ if needed

Connect supported tools at the agent layer, not as arbitrary knowledge-base sources. Configure identity, consent and minimal scopes.

4
Attach Fabric IQ

Use a supported Fabric tool or integration for trusted metrics and semantics; keep this distinct from knowledge-base source registration.

5
Govern & Ship

Test denied access, stale permissions and answer quality. Use GA multi-turn evaluation, insights and agent optimizer; approve changes before deployment.

Commercial

Licensing & Availability

Microsoft IQ adds no new SKU or subscription. Underlying licenses, capacity, model calls, retrieval and web usage still carry their own terms and meters. Confirm prerequisites for each integration.

Work IQ

The CLI and MCP integrations have different prerequisites and billing paths. Some experiences require Microsoft 365 Copilot; others use Copilot Credits and a configured billing plan.

Check experience-specific prerequisites

Fabric IQ

Fabric IQ items consume Microsoft Fabric capacity. Confirm supported capacity, region, tenant settings and feature-specific status before use.

Microsoft Fabric capacity

Foundry IQ

Foundry IQ uses the existing Foundry IQ (Azure AI Search) service meters and supported model usage for agentic retrieval. Serverless adds consumption-based compute and indexed-storage pricing; confirm current regional and SKU support.

Search service + model usage

Web IQ

Consumption-based Web IQ usage requires a paid Azure subscription. Azure credits do not work for Web IQ. Zero Query Logging is available to eligible Azure managed customers in regulated industries; verify eligibility and terms.
