The Four IQ Platforms

Each IQ serves a different role in the knowledge stack. Learn what each one does, how it works, and when to reach for it.

GA · 16 June 2026

Work IQ

Your organization's digital work life — for Microsoft 365 agents

What it is

M365 Context MCP Servers Memory
  • Intelligence layer for agents working over Microsoft 365 signals and activity
  • Three layers: Data (who, what, where), Memory (personal context), Inference (reasoning over work)
  • Catalog of MCP servers agents can call: Copilot, Calendar, Mail, SharePoint, OneDrive, Teams, User, Word
  • Available via Copilot Studio, Agent 365, or standalone CLI

How it works

  • Agent calls a Work IQ MCP server (e.g., mcp-mail, mcp-sharepoint)
  • MCP server queries the Microsoft Graph on behalf of the signed-in user
  • Delegated Entra ID permissions enforce user-scoped access automatically
  • Memory layer persists user-specific context across sessions
  • Returns structured results the agent can reason over

When to use it

  • Personal productivity agents: email triage, meeting prep, document drafting
  • "Summarize my week across Teams, email, and calendar"
  • Agents that need activity context — who's collaborating with whom on what
  • Shipping into Teams, Outlook, or M365 Copilot surfaces
  • When you already have M365 Copilot licenses

Fabric IQ

Semantic intelligence for your business data — for analytic & operational agents

What it is

Business Ontology Semantic Graph Data Agents
  • New Microsoft Fabric workload that turns Fabric from a data platform into an intelligence platform
  • Six items: Ontology, Plan, Graph, Data Agent, Operations Agent, Power BI semantic models
  • Ontology captures your business entities, relationships, and KPIs so agents speak your language
  • Graph reasons over connected enterprise data in OneLake

How it works

  • Define entities (Customer, Order, Project) and their measures once in the Ontology item
  • Data Agents answer natural-language analytics questions grounded in your data model
  • Operations Agents monitor, act, and trigger workflows on data events
  • Queries cascade through Graph + OneLake with row/column-level security preserved
  • Plugs into Foundry IQ as a first-class knowledge source

When to use it

  • Agents that need to reason over structured business data: revenue, inventory, customers, projects
  • Analytic / BI copilots with correct terminology and metric definitions
  • Cross-domain questions: "Which customers with open support tickets also have renewals this quarter?"
  • Operational automation: auto-detect inventory risks, trigger reorder workflows
  • When you're already on Microsoft Fabric — Fabric IQ is included in your SKU

Foundry IQ

Unified knowledge endpoint for agents — the aggregator across your ecosystem

What it is

Unified Retrieval Agentic Planning Context Engineering
  • Context engineering platform in Microsoft Foundry — one retrieval endpoint across every knowledge source your agent needs
  • Built on Azure AI Search, extends it with agentic retrieval, query planning, and ranking
  • Concepts: Knowledge Bases (collections of sources) and Knowledge Sources (indexed files, Fabric IQ, Work IQ, web, SharePoint)
  • Three retrieval reasoning tiers: minimal, low, medium — trade latency for depth

How it works

  • Agent makes one call to a Foundry IQ knowledge base
  • A query-planning LLM (GPT-4o, GPT-4.1, or GPT-5) decomposes the question into sub-queries
  • Sub-queries fan out across indexed content, Fabric IQ, Work IQ, web, and remote sources in parallel
  • Results are ranked, deduplicated, and consolidated with citations
  • Entra ID, Purview, and data-source ACLs enforced on every hop

When to use it

  • Any agent that needs knowledge from more than one source (the vast majority)
  • Enterprise RAG patterns — replace hand-written retrieval orchestration
  • Multi-domain agents: combines M365 context (Work IQ) + business data (Fabric IQ) + domain docs
  • When you need a single governed, auditable retrieval layer with Purview monitoring
  • Pro-code agents on Foundry or low-code agents in Copilot Studio

Web IQ

The live world outside your tenant — Bing-powered grounding built for agents

What it is

Web Grounding Bing-Powered Agent-Optimized
  • Live web grounding optimized for agent search patterns — not human browsing behavior
  • The fourth pillar of Microsoft IQ, completing the picture: Work IQ knows your people, Fabric IQ knows your business meaning, Foundry IQ aggregates both, Web IQ grounds in the external world
  • Built on the Bing index, surfaced for agents rather than for search-results pages
  • Currently limited access — confirm eligibility before designing it into a committed architecture

How it works

  • Agent issues a retrieval call for external, current information
  • Web IQ returns results shaped for machine reasoning — structured, citable, and de-duplicated
  • Retrieval patterns are tuned for the multi-hop, iterative way agents search, rather than a single ranked page list
  • Pairs with Foundry IQ so one agent can blend internal knowledge and live external facts in a single answer

When to use it

  • Answers that go stale: market moves, competitor announcements, pricing, regulatory changes
  • Research and analyst agents that must cite public sources
  • Any workflow where “what changed this week?” matters more than what is in your data estate
  • Not for internal knowledge — that is Foundry IQ, Fabric IQ, and Work IQ territory

End-to-End

Building a Smarter Agent with IQ

The canonical pattern: pick your surface, wire it to Foundry IQ, and let Foundry IQ reach into Work IQ, Fabric IQ, and other sources on your behalf.

1
Define the Agent

Build in Copilot Studio (no/low-code) or with the Foundry Agent SDK (pro-code). Choose your model.

2
Create a Foundry IQ Knowledge Base

Start with one knowledge base. Add sources: docs, SharePoint, Work IQ, Fabric IQ.

3
Attach Work IQ

Plug in MCP servers for Mail, Calendar, SharePoint — so the agent sees user activity context.

4
Attach Fabric IQ

Register Fabric IQ ontology + Data Agents to ground answers in business metrics and semantics.

5
Govern & Ship

Apply Purview policies, set retrieval reasoning tier, deploy to Teams, web, or your app.
