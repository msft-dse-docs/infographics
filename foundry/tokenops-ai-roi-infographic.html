The bill does not come from a model call.
It comes from a run.

A gateway sees a request. A budget cap sees the month. But an AI agent spends money inside a live execution graph — loops, retries, tool calls, RAG, sub-agents, and hand-offs. If you cannot attribute spend to the run, you cannot control the business case.

Microsoft Foundry cost loop

Three decisions. Three speeds. One investment system.

Foundry's optimization story is not one feature. It is a loop: optimize the request at runtime, optimize the workflow over time, and govern spend continuously.

Optimize each request at runtime

  • Model router: match prompt difficulty to cost / quality / balanced modes
  • Deployment choices: Standard, Priority, Provisioned Throughput, Batch; Global, Data Zone, Regional
  • Prompt + semantic caching: reuse repeated context
  • Foundry IQ: retrieve only the relevant, permission-aware context

Optimize the agent workflow over time

  • Agent optimizer: test prompts, models, tools and skills against your evaluators
  • Toolboxes: send only the tools a request needs
  • Memory: carry context without resending full history
  • Fine-tuning: let a smaller model meet the task

Govern spend continuously

  • Azure API Management AI Gateway: token limits, quotas, caching
  • Azure Cost Management: budgets, alerts, chargeback
  • Agent 365: tenant-wide agent cost policies and departmental chargeback
  • Foundry roadmap: native budgets, enforcement, agent/session attribution
Cost equation

Two things set the bill: tokens per call and calls per run.

Agent cost is the sum of every input token, output token, loop, retry and sub-agent. That means you need to manage both the size of each call and the shape of the run.

cost of a run = sum over calls of (input tokens × input price + output tokens × output price)
calls per run = loop depth × fan-out breadth

Therefore guard: tokens per call · loop depth · fan-out · total run ceiling
TokenOps pattern

Real-time, run-scoped cost control.

TokenOps carries a run ID through the execution graph, tags every call to the run, counts it against one shared ledger, and applies policy before the next action executes.

Request-level controls

Gateways cap, meter and route individual completion requests. Useful — but blind to loops, retries, sub-agents and hand-offs across processes.

Unit of control: request / key
→
Run ID + shared ledger

Run-scoped controls

TokenOps sees the agent run as a graph. Every call is attributed to the same run budget, even across multiple agents, providers, processes and queues.

Unit of control: run / agent type / user segment
Instrument

Record every call

Model client, tools, RAG and agent nodes emit cost events with run, agent and step tags.

Account

Write to one ledger

A shared store prevents the two-agent bug: each process thinking it owns the full budget.

Enforce

Steer, then halt

Policies shrink, reroute or correct the next call; HALT is the circuit breaker of last resort.

Policy layer

The controls that prevent runaway spend.

TokenOps separates the decision plane from the execution path. Policy decisions are prepared out of band; the in-path wrapper reads spend and applies allow / shrink / reroute / refuse before each call.

cost_budget

Total run ceiling; halt when cap is reached.

pre_call_worst_case

Refuse a next call whose worst case cannot fit.

cost_guard

At ~80% spend, steer cheaper: downgrade, trim, once.

step_cap

Stops runaway loop depth.

progress_guard

Detects repeated action/result loops.

output_runaway

Caps degenerate long output.

fanout_cap

Controls sub-agent breadth.

context_cap

Prevents RAG and history bloat.

retry_cap

Stops repeated weak-tool-result retries.

lineage

Spend tree: which agent and which call spent what.

Bring to the next review

Four questions AI leaders should ask before funding scale.

If you cannot answer one of these today, that is where to start. Together, they turn AI from experiment spend into accountable investment.

Do we know what we are paying for?

Cost should be visible by model, app, agent, workflow and run — not just one cloud line item.

Are we paying the right amount for each request?

Use model router, caching, deployment choices, Foundry IQ and fine-tuning to match cost to difficulty.

Are our agents getting more efficient over time?

Use agent optimizer, toolboxes, memory and evaluators so quality improves while waste falls.

Do our limits hold when usage spikes?

Use APIM gateway controls today; add run-scoped TokenOps where runaway runs are the risk.

Customer implementation path

A practical 30 / 60 / 90 path to agent ROI.

The fastest way forward is not a giant governance program. Start with one high-value workflow, instrument it, then add controls at the right unit: request, workflow, run, tenant.

30

Baseline the work

Choose one agent workflow. Capture task value, model calls, input/output tokens, loop depth, tool calls and current cost.

60

Optimize the request

Apply model router, caching, shorter context, Foundry IQ, smaller tuned models and deployment choices.

75

Control the run

Add run IDs, shared ledger, token lineage, and policies that steer or halt before the runaway spends.

90

Scale with governance

Publish app/agent chargeback, budget alerts, APIM gateway quotas, and Agent 365 tenant policies.
