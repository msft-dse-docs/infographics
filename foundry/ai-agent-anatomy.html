The Shift

We stopped asking which model — because the model stopped being the variable.

In 2023–24 the intelligence lived in the wording: whoever wrote the cleverest instruction won. In 2025–26 the intelligence lives in the architecture: whoever builds the better scaffold wins. Each stage absorbed the last — prompt engineering did not die, it became one component of something larger.

The Sixteen Organs

Every agent is built from these parts.

Ten organs from the original field guide — and six that did not exist at your last design review. Ship with all sixteen and your agent behaves. Skip one and it breaks, usually in the way the missing organ would have prevented.

1. Instructions

the heart — purpose, persona, constraints

The agent's constitution. Who it is, what it's for, what it must never do. Everything else serves this.

  • Role & persona — "You are a Tier-1 support triage agent."
  • Goals & success criteria — what "done" looks like
  • Hard constraints — policy, compliance, refusal rules
  • Tone & output shape — format, voice, length
Without itAgents drift. Same prompt, wildly different outputs, no way to audit why.

2. Model

the brain — reasoning engine

The LLM that reads, thinks, and writes. Pick for the job: reasoning depth vs. speed vs. cost vs. context window.

  • Frontier — GPT-5.x, Claude, Grok for complex reasoning
  • Workhorse — GPT-4o-class for most tasks, cheaper and fast
  • Small & local — Phi-class for edge, low-latency, on-device
  • Fine-tuned — when domain idioms matter more than raw IQ
Without the right oneEither overpaying 10× for simple tasks, or watching your agent face-plant on the ones that matter.

3. Knowledge & Context

the senses — what it sees and hears

Everything the agent pulls in before it answers: retrieval, grounding sources, real-time signals, the user's current situation.

  • Retrieval — vector + keyword search over your corpus
  • Grounding sources — SharePoint, OneDrive, Fabric, web
  • Federated knowledge — live queries to systems of record
  • Session context — user intent, recent turns, attachments
Without itConfident hallucination. Your agent invents policies, invents customers, invents facts.

4. Tools

the hands — how it acts on the world

Functions, APIs, and MCP servers the agent can invoke. This is the line between "talks about work" and "does work."

  • Function calls — typed, schema-defined capabilities
  • MCP servers — reusable, portable tool catalogs
  • Connectors — Logic Apps, Graph, Power Platform (~1,400+)
  • Code interpreter — sandboxed compute for ad-hoc work
Without themA chatbot. Can describe the fix. Can't apply it.

5. Skills

muscle memory — trained procedures

Named, reusable playbooks that bundle instructions, tool sequences, and examples for a recurring job. Not code — packaged know-how.

  • Composable — one agent, many skills; one skill, many agents
  • Conditionally loaded — cited only when the trigger fires
  • Expert-encoded — your best ops patterns, distilled
  • Versioned — improve without rewriting the agent
Without themEvery task re-derived from scratch. Brittle, inconsistent, unscalable across a team of agents.

6. Memory

the hippocampus — what it remembers

State that persists beyond a single turn: short-term scratch, long-term facts about the user, episodic traces of past sessions.

  • Short-term — the working conversation window
  • Long-term — user preferences, prior decisions, vocabulary
  • Episodic — "last time we talked about X, we decided Y"
  • Shared — team-level memory across many agents
Without itPermanent amnesia. Users repeat themselves. Personalization is impossible.

7. Guardrails

the ribcage — protecting what matters

Input, output, and runtime safety. Not a feature bolt-on — an always-on perimeter.

  • Input shields — prompt injection, jailbreak detection
  • Output filters — PII, toxicity, grounded-ness checks
  • Policy checks — tool-use allowlists, data boundaries
  • Human-in-the-loop — approval gates for high-stakes actions
Without themA single jailbreak or prompt injection exfiltrates data, books travel, or sends the wrong email.

8. Orchestration & Planning

the nervous system — how it decides

The loop that turns "answer this" into "plan, act, observe, re-plan." Single-agent, multi-agent, hand-offs, parallel branches.

  • ReAct loop — reason → act → observe → repeat
  • Plan-and-execute — decompose first, then run
  • Multi-agent — specialists with a router or supervisor
  • Hand-offs — escalate to a peer agent or a human
Without itOne-shot answers only. Agent can't recover from its own mistakes or chain more than a single tool call.

9. Identity & Permissions

the badge — who the agent acts as

Agents are first-class workforce identities. They authenticate, inherit permissions, and leave audit trails — just like employees.

  • Entra agent identity — its own principal, not a shared key
  • Delegated access — act on behalf of the user, within scope
  • Least-privilege tools — only the APIs it needs
  • Audit trail — every action attributable to this agent
Without itOver-privileged service principals. Compliance cannot prove what the agent did, or didn't do.

10. Observability & Evals

the stethoscope — how you know it's healthy

Tracing, logging, evals, and telemetry. The difference between "it works on my demo" and "it works at scale."

  • Traces — every step, tool call, token, and latency
  • Evals — accuracy, groundedness, safety, task success
  • Red-teaming — adversarial tests before production
  • Production monitoring — drift, cost, user satisfaction
Without itYou're flying blind. Regressions go unnoticed until a user complains on Teams.

11. Reflex Arc

the startle response — it wakes itself up

Triggers, schedules and events replace the chat box. The agent perceives, decides and acts with nobody watching.

  • Copilot Studio autonomous agents — GA
  • Foundry Routines — Preview, Jun 2026
  • Microsoft 365 Workflows agent — event-driven work
  • The test — does anything happen when nobody types?
Without itYour agent is an expensive search box that only works when someone remembers it exists.

12. Opposable Thumbs

the hands, upgraded — it clicks the button itself

Computer use and browser control let an agent drive the systems that never got an API — by looking at the screen.

  • Copilot Studio computer use — GA, 26 May 2026
  • Foundry Browser Automation — Preview
  • Windows 365 for Agents — Preview, isolated sessions
  • Pair with — identity + approval gates, always
Without itYour legacy estate stays invisible to every agent you build.

13. Spine

the backbone — work outlives the session

Checkpointing and hydration let a run pause, fail, resume and finish hours or days later — exactly where it stopped.

  • Agent Framework workflows — GA, 3 Apr 2026
  • Foundry hosted agents — managed session state
  • Azure Durable Functions — Preview
  • The test — kill the process mid-run; does it finish?
Without itEvery crash restarts from zero — so nothing long or valuable can ever be trusted to an agent.

14. Metabolism

energy budget — tokens, models, cost

The agent budgets its own energy. Route to the cheapest capable model, search for tools instead of loading them all, expire what it no longer needs.

  • Foundry model router — GA, routes 28 models
  • Tool Search — Preview; 97%+ fewer tokens at 1,000 tools
  • 98.7% fewer tokens — MCP tools invoked as code, not loaded as schemas (150,000 → 2,000)
  • Memory TTL — Preview; context that expires
Without itThe pilot works beautifully and the invoice quietly kills the programme.

15. Face

voice and expression — more than a text box

Speech-to-speech and streaming generative UI replace the chat transcript as the primary surface. Interruption is the proof it changed.

  • Copilot Studio voice agents — GA, May 2026
  • Foundry Voice Live API — Preview
  • MCP Apps, AG-UI, A2UI — emerging UI protocols
  • Barge-in — talk over it mid-sentence and it yields
Without itYou built a colleague and handed it a command line.

16. Learning

plasticity — it improves from its own traces

A closed loop that turns production runs into better instructions, new skills and a smarter model choice. The organ that compounds.

  • Foundry Agent Optimizer — Preview
  • Microsoft 365 Copilot Tuning — Preview
  • Procedural memory — Preview; skills that rewrite themselves
  • Feeds on — the traces Observability already collects
Without itYour agent is exactly as good on day 300 as it was on day one.

The Organ You Cannot Skip

Each new organ widens the blast radius.

Security stopped being a review gate and became an architecture decision. The reason is a specific, recognisable combination — and the six new organs hand it to your agent by default.

Private data

The agent can reach something worth stealing.

Untrusted content

It reads something an attacker can influence.

External comms

It can send data somewhere you don’t control.

The lethal trifecta. An agent with all three can be talked into exfiltrating your data. Autonomy, browsing and computer use hand it all three by default — which is why Reflex Arc and Opposable Thumbs cannot ship without Identity and Guardrails already in place.

Framing: Simon Willison, 2025 · Mitigations: Entra Agent ID, least-privilege tools, human approval gates, VM-isolated sessions.

Why this outlasts any one stack

The plumbing between agents moved to the Linux Foundation — MCP and A2A are both governed under the Agentic AI Foundation. There are 10,000+ published MCP servers across half a billion SDK downloads a month, and on 28 July 2026 MCP’s stateless core shipped, so any request can land on any instance behind a plain load balancer. Your tools now outlive your platform choice — the protocol under them is production infrastructure, not an experiment.

Diagnostic

Is your agent fully formed?

Score yourself. Sixteen boxes, no partial credit. 0–8 = prototype (impressive on Friday, dangerous on Monday). 9–13 = production-shaped (works until something unexpected happens). 14–16 = actually autonomous (you can leave it running and sleep). The organ you are least sure about is the one that will page you at 3am.

Pathology

The six ways agents usually fail.

Every failure mode maps to a missing or malformed organ. Use this list in post-mortems — the real cause is almost always one of these.

Anti-pattern 1

The Clever Prompt

All instructions, no tools, no retrieval. "Prompt engineering" as a whole strategy.

→ Add knowledge and tools. Clever prompts alone scale to demos, not to production.

Anti-pattern 2

The Tool Hoarder

Forty tools attached, no skills, no orchestration. Model drowns picking the right one.

→ Bundle tools into skills. Load skills conditionally based on the task.

Anti-pattern 3

The Ungrounded Oracle

Big model, slick persona, zero retrieval. Confidently wrong about your own business.

→ Ground every factual claim in retrieved knowledge. Refuse when unsure.

Anti-pattern 4

The Amnesiac

No memory. Users explain themselves and their context on every turn.

→ Add short-term summarization and at least a user-preference memory surface.

Anti-pattern 5

The Unleashed Intern

Broad tool access, no guardrails, no identity scoping. One prompt injection from disaster.

→ Entra identity + least-privilege tools + input/output shields + approval gates.

Anti-pattern 6

The Black Box

No traces, no evals. Every regression is a surprise; every incident is a forensic dig.

→ Emit traces by default. Run evals on every change, not just before launch.

The Ladder

From skeleton to athlete.

Agents don't ship fully formed. They grow. Use these rungs to locate your agent today — and see what's next.

Rung 1

Skeleton

  • Instructions only
  • Single model call
  • No tools, no retrieval
  • Great for demos, dangerous in prod
Rung 2

Functional

  • + Knowledge (RAG)
  • + A handful of tools
  • + Basic guardrails
  • Does useful work, breaks under load
Rung 3

Production-ready

  • + Skills catalog
  • + Memory (short + long)
  • + Entra identity & scoping
  • + Traces and evals on every change
Rung 4

Autonomous

  • + Reflexes — it starts itself
  • + Thumbs, spine, metabolism
  • + Self-improvement from traces
  • Runs without you, and survives the restart

Rung four used to mean multi-agent. Now it means the agent runs without you.

The honest counter-argument

Better models are already deleting parts of this scaffold — and that is fine. A 100-line agent now scores above 74% on SWE-bench Verified. Build scaffolding that is cheap to delete, and invest durably in the parts that survive a model upgrade.

Being absorbed by better models

Elaborate tool interfaces, prompt chains, routing glue, hand-tuned retries. The clever parts were scaffolding for a weaker model.

Not being absorbed — invest here

Memory across sessions, orchestration, verification, identity, governance. A more autonomous agent needs more verification, not less. These grow as models improve.

The bitter lesson eats the cleverness. It does not eat the engineering.
