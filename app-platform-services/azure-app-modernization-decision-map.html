Modernize With Intent.
Do Not Move Yesterday’s Problems to Tomorrow’s Cloud.

Application modernization is not a single path to Azure. It is a portfolio decision: what to retire, what to retain, what to move fast, what to replatform, what to refactor, what to rearchitect, what to rebuild — and where GitHub Copilot can safely accelerate the work.

The provocative truth: “Lift and shift” is not a strategy. It is a treatment for the workloads that deserve it. The architect’s job is to decide which workloads deserve a quick move, which deserve a better platform, and which should stop existing.

The question is not “Can this run on Azure?”
The question is “What should this become?”

Azure supports every modernization path — but customer value comes from choosing the right path per workload. A stable system may only need rehost. A brittle monolith may need rearchitect. A commodity process may need replace. A dead system may need retire.

Modernization is a workload treatment plan

Start with business driver, not landing zone.

Microsoft’s Cloud Adoption Framework now presents the migration strategies as a practical decision set: Retire, Retain, Rehost, Replatform, Refactor, Rearchitect, Rebuild, or Replace. For customer conversations, treat Retire and Retain as governance gates — then use the six active routes to drive the modernization plan.

Two gates architects should not skip

The most mature modernization plans also say what not to move and what not to touch yet.

Retire
Decommission low-value, redundant or obsolete workloads before they consume migration budget.
Retain
Keep stable, compliant workloads where they are — manage with Azure Arc or revisit in a later wave.
Choosing the right “R”

Each route has a different architectural bet.

The wrong “R” creates rework. The right one makes the next decision easier: operational model, platform target, data dependency, security boundary, and developer workflow.

Fastest move

Rehost

Use when workload is stable, compatible, low risk, and no modernization is needed for ~2 years. Target: Azure VMs. Watch-out: you carry technical debt forward.

Ops reduction

Replatform

Use when PaaS or container hosting reduces OS, patching, reliability or licensing burden. Target: App Service, Azure SQL, Container Apps.

Code health

Refactor

Use when code changes reduce technical debt, improve observability, adopt Azure SDKs, or optimize performance and cost.

Architecture unlock

Rearchitect

Use when the monolith blocks scale or innovation. Split capabilities, introduce eventing, APIs, microservices, or service decomposition.

New cloud-native

Rebuild

Use when the existing system is too outdated or inflexible. Build with modern frameworks, managed services, DevOps, observability and security from day one.

Buy, don’t build

Replace

Use when SaaS, low-code, or AI-native solutions meet the business need better than custom maintenance. Shift dev effort to differentiators.

Target architecture choices

Map the “R” to the Azure platform target.

A modernization route is incomplete until you choose the runtime and operating model. These are the most common landing patterns architects should compare.

Web + APIs

Azure App Service

  • Best for web apps and APIs with managed hosting
  • Strong fit for replatforming .NET and Java apps
  • Reduces OS and patching overhead
Serverless containers

Azure Container Apps

  • Best for microservices, APIs and event-driven services
  • Good path from containerization to scale-to-zero
  • Pairs well with Dapr and KEDA patterns
Enterprise Kubernetes

AKS / AKS Automatic

  • Best where Kubernetes is already the operating model
  • Use for complex orchestration and platform engineering
  • AKS Automatic simplifies cluster management
Data modernization

Azure SQL / Cosmos DB / PostgreSQL

  • Move data off self-managed databases where possible
  • Pair database migration with app replatform or refactor
  • Measure latency and data gravity early
AI-enabled apps

Microsoft Foundry

  • Add model catalog, agents, evaluations and safety
  • Use after modernization to add AI features responsibly
  • Connect app telemetry to business outcomes
Hybrid / deferred

Azure Arc / Azure Local

  • Use when workloads must be retained temporarily
  • Apply governance without forcing immediate migration
  • Reassess in later waves
Architect review questions

Eight questions that prevent modernization theater.

Use these in a TDM workshop to move from aspiration to a defendable workload treatment plan.

What business driver justifies change?

Cost, resilience, agility, AI adoption, compliance, developer productivity or end-user experience?

Will rehosting create duplicate effort?

If modernization is likely within two years, rehost may just delay the real work.

What can be retired or retained?

Do not spend modernization budget on obsolete systems or stable workloads with low ROI.

Which target platform removes operations?

Prefer managed services where they reduce patching, scaling, backup and incident burden.

What does Copilot modernization see in code?

Run assessment before debating architecture. Let code, dependencies and issues shape the plan.

Where is the security boundary?

Identity, secrets, network access, data classification and logging must be designed before migration.

How will success be measured?

Choose metrics: deployment lead time, response time, reliability, cost, observability coverage or dev effort shifted.

What pattern can be reused?

Use Copilot-generated migration patterns and custom skills to standardize fixes across teams and apps.

Recommended workshop flow

A practical modernization path for TDMs and architects.

Start with the portfolio, then the code, then the target. Do not pick Kubernetes, PaaS or AI before the workload tells you what it needs.

Inventory

Use Azure Migrate and stakeholder interviews to map apps, dependencies, business criticality and constraints.

Rationalize

Assign Retire / Retain gates, then select one of the six active routes for each workload.

Assess code

Run GitHub Copilot modernization assessment and AppCAT-style reports against candidate workloads.

Select target

Compare App Service, Container Apps, AKS, Azure SQL, Arc, Microsoft Foundry and SaaS options.

Industrialize

Turn commits into reusable migration patterns, automate tests, generate IaC, and repeat by wave.

Modernization is not a destination.
It is a decision discipline.

Move the workloads that deserve speed. Replatform the ones that deserve managed operations. Refactor and rearchitect where the business case is real. Rebuild or replace where legacy has become the constraint. And let GitHub Copilot accelerate the path — without removing architectural accountability.
